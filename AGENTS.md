# Правила работы над проектом

Этот файл читают разработчики и AI-агенты перед началом работы. Он описывает, как здесь принято работать. Что именно строить, описано в `docs/PLAN.md`.

## Что это за проект

Сайт-резюме владельца репозитория на трёх языках (de, en, ru) с концепцией «резюме с доказательствами». Репозиторий публичный: его код и история входят в портфолио владельца, их будут читать работодатели.

## Источники правды

| Вопрос | Документ |

| Требования к форме связи и её защите | `docs/CONTACT_FORM.md` |
| Дизайн-направление и референсы | `docs/DESIGN.md` |

Если документы противоречат друг другу или задаче, остановись и спроси владельца. Если решение изменилось, запиши это в `docs/DECISIONS.md`.

## Как работаем

- **Этапами.** Берём один этап из плана, доводим до критерия «Готово, когда» и только потом переходим к следующему. Работу сверх этапа предлагаем владельцу, а не делаем молча.
- **Через тесты.** Перед кодом составляется список тестов для поведения этапа. Затем красный тест, минимальная реализация, рефакторинг. Тесты нельзя удалять, ослаблять или пропускать ради зелёного прогона.
- **С проверкой.** Этап готов после lint, проверки типов, тестов, сборки и проверки интерфейса в настоящем браузере (Playwright) на десктопе и мобильном.
- **По актуальной документации.** Версии в документах проверены 22.11.2026 и могли уйти вперёд. Перед использованием API библиотеки сверяйся с её текущей документацией (Context7, если он доступен). Справочник установленной версии Next.js есть в `node_modules/next/dist/docs/`.
- **Дизайн по референсам.** Новое визуальное решение сначала сверяется с референсами (Lazyweb, если он доступен) и показывается владельцу прототипом.
- **Минимальными изменениями.** Без абстракций и зависимостей «на будущее». Новая зависимость берётся версией старше 7 дней.

## Что нельзя

- **Секреты и личные данные в репозитории.** Токены, ключи, `.env`, телефон, почта и адрес владельца не попадают ни в код, ни в историю, ни в тестовые данные. Причина: репозиторий публичный.
- **Выдуманные факты о владельце.** Всё, чего нет в подтверждённом контенте, уточняется у него. Причина: сайт является резюме, и любая неточность бьёт по доверию.
- **Ненастоящие доказательства.** Панель показывает реальные данные сборки, CI или ответа сервера. Если данных нет, панель скрыта. Причина: вся концепция держится на проверяемости.
- **Ослабление защиты формы.** Лимиты из `docs/CONTACT_FORM.md` заданы владельцем и не меняются без его решения.

## Git

- Коммиты и пуши выполняются только по явной просьбе владельца.
- Сообщение коммита объясняет, зачем сделано изменение.
- Чужие незакоммиченные изменения не трогаем.

## Команды

Запускай из корня репозитория. Нужен Node.js 22 (не ниже 22.13.0); версия pnpm закреплена в `package.json`. Для каркаса `.env` не нужен.

| Задача | Команда |
|---|---|
| Установка | `pnpm install --frozen-lockfile` |
| Dev-сервер | `pnpm dev` (открой `http://localhost:3000/de`, `/en` или `/ru`) |
| Линтер и форматирование | `pnpm lint` и `pnpm format:check` |
| Проверка типов | `pnpm typecheck` |
| Unit-тесты | `pnpm test:unit` |
| Интеграционные тесты | Появятся вместе с формой связи и Redis на этапе 4 |
| Сборка | `pnpm build` |
| Запуск сборки | `pnpm start` |
| Сквозные тесты | Один раз `pnpm exec playwright install chromium`, затем `pnpm build` и `pnpm test:e2e` |

Playwright сам поднимает standalone-сервер на порту 3100 и проверяет все локали в десктопном и мобильном Chromium. В CI браузер устанавливается с системными зависимостями (`pnpm exec playwright install --with-deps chromium`).

## Общение

С владельцем общаемся по-русски. В конце каждого этапа нужен короткий отчёт: что сделано, что и как проверено, отклонения от плана, открытые вопросы, что требуется от владельца.
