# Форма связи: требования и защита

Спецификация для этапа 4. Числа из раздела «Требования владельца» меняются только по его решению.

## Требования владельца

- Сообщение не длиннее 1024 символов.
- С одного IP принимается не больше одного сообщения за 5 минут.
- Форма защищена от перегрузки сервера большими запросами.
- Сообщения приходят владельцу в Telegram.

## Поля

| Поле | Правило |
|---|---|
| `name` | 1–80 символов |
| `contact` | 1–120 символов: почта, Telegram или другой способ ответить |
| `message` | 1–1024 символа |
| `locale` | `de`, `en` или `ru` |
| поле-ловушка | Скрыто от людей и должно остаться пустым |

Длина считается как `string.length` в JavaScript, то есть так же, как нативный атрибут `maxlength`, и одинаково на клиенте и сервере. Сообщение из одних пробелов не принимается. Управляющие символы, кроме перевода строки и табуляции, отклоняются. Неизвестные поля отклоняются.

## Интерфейс запроса

- `POST /api/contact`, тело в JSON.
- `GET /api/contact/status` возвращает оставшийся кулдаун для IP посетителя. Ответ не кэшируется.

| Ситуация | Статус | Код в теле ответа |
|---|---|---|
| Принято и доставлено | 200 | нет |
| Некорректный JSON | 400 | `bad_json` |
| Метод не `POST` | 405 | `method_not_allowed` |
| Тело больше 8 КБ | 413 | `too_large` |
| Тип содержимого не JSON | 415 | `unsupported_type` |
| Ошибка валидации | 422 | `invalid` с перечнем полей |
| Кулдаун или слишком частые запросы | 429 | `cooldown` или `rate_limited`, заголовок `Retry-After` |
| Сбой доставки в Telegram | 502 | `delivery_failed` |
| Суточный потолок или недоступен Redis | 503 | `daily_limit` или `unavailable` |

## Слои защиты

Проверки идут от дешёвых к дорогим, чтобы мусорный запрос отсекался как можно раньше.

1. **Caddy.** Тело запроса к `/api/*` не больше 8 КБ, задан таймаут чтения тела. 1024 символа занимают в UTF-8 до 3 КБ, поэтому 8 КБ хватает с запасом.
2. **Метод и тип.** Только `POST` с `Content-Type: application/json`.
3. **Размер в обработчике.** Проверка `Content-Length` и потоковое чтение с жёстким потолком 8 КБ. Потолок при чтении нужен потому, что заголовка может не быть или он может быть неверным.
4. **Лимит частоты.** Не больше 10 запросов в минуту с одного IP на эндпоинт. Он отсекает перебор невалидными запросами, которые не занимают кулдаун.
5. **Разбор и валидация.** Сначала JSON, затем схема zod.
6. **Ловушки для ботов.** Если заполнено поле-ловушка или форма отправлена быстрее чем через 2 секунды после открытия, сервер отвечает 200, но сообщение не доставляет и кулдаун не занимает. Это эвристика против простых ботов, а не средство защиты. Способ измерения времени выбирает разработчик.
7. **Кулдаун.** Атомарная операция `SET <ключ> 1 NX EX 300` в Redis. Если ключ уже есть, ответ 429 с оставшимся временем. Атомарность исключает двойную отправку при параллельных запросах.
8. **Суточный потолок.** Общий счётчик сообщений за сутки, по умолчанию 100. Он защищает бота от распределённого спама.
9. **Доставка.** Telegram Bot API `sendMessage` обычным текстом, без `parse_mode`, чтобы текст посетителя не мог сломать разметку. Таймаут 5 секунд, одна повторная попытка.

Правила вокруг кулдауна:

- Невалидный запрос кулдаун не занимает.
- При сбое доставки ключ кулдауна удаляется, суточный счётчик откатывается, и посетитель может повторить отправку.
- Если Redis недоступен, форма отвечает 503 и ничего не отправляет: без лимитов бот остаётся без защиты. Интерфейс в этом случае показывает запасной способ связи.

## IP посетителя

- В проде запрос проходит цепочку: Cloudflare, туннель, Caddy, приложение. Caddy доверяет только внутренней сети, берёт IP из `CF-Connecting-IP` и передаёт его приложению в одном заголовке. Приложение читает только этот заголовок.
- Заголовкам от клиента, включая `X-Forwarded-For`, приложение не доверяет.
- Доверять `CF-Connecting-IP` можно потому, что сервер недоступен в обход туннеля. Если схема хостинга изменится, это правило нужно пересмотреть.
- IPv4 используется целиком, IPv6 по префиксу /64. Иначе один посетитель обходит лимит, перебирая адреса своей подсети.

## Приватность

- Ключи в Redis содержат не IP, а HMAC-SHA256 от него с секретом. Срок жизни ключа кулдауна 5 минут.
- В логи не попадают ни IP, ни текст сообщений.
- Сервер не хранит сообщения, он только пересылает их в Telegram.
- Под формой стоит строка о том, какие данные обрабатываются, со ссылкой на страницу о защите данных.

## Интерфейс

- Одна колонка: имя, контакт, сообщение, кнопка. Счётчик `0/1024` в углу поля сообщения.
- Кнопка заблокирована, пока форма невалидна, идёт отправка или действует кулдаун.
- Состояния: ожидание, отправка, успех, ошибка валидации, ошибка сети или сервера, кулдаун с обратным отсчётом.
- Все тексты на трёх языках с правильными формами числительных.
- Доступность: подписи полей, объявление статуса для экранных дикторов, управление с клавиатуры.

## Настройки

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Доставка. Значения задаёт владелец |
| `REDIS_URL` | Хранилище лимитов |
| `IP_HASH_SECRET` | Секрет для HMAC от IP |
| `CONTACT_DAILY_CAP` | Суточный потолок, по умолчанию 100 |

Секреты задаются только через окружение и не попадают в репозиторий.

## Обязательные тесты

Интеграционные тесты работают с настоящим Redis и подставным Telegram.

1. Сообщение в 1024 символа принимается, в 1025 отклоняется с 422.
2. Пустое сообщение и сообщение из одних пробелов дают 422.
3. Тело больше 8 КБ даёт 413, в том числе при потоковой отправке без `Content-Length`.
4. Неверный метод даёт 405, неверный тип содержимого 415, некорректный JSON 400, неизвестное поле 422.
5. Второе валидное сообщение с того же IP в течение 300 секунд даёт 429 с `Retry-After`. После истечения срока сообщение принимается.
6. Разные IP не влияют друг на друга.
7. Два адреса IPv6 из одной /64 делят кулдаун, из разных /64 не делят.
8. Невалидный запрос не занимает кулдаун.
9. Сбой Telegram даёт 502, кулдаун освобождается, следующая попытка проходит.
10. Подделанный `X-Forwarded-For` не меняет ключ лимита.
11. Одиннадцатый запрос за минуту с одного IP даёт 429.
12. При достигнутом суточном потолке ответ 503.
13. Заполненное поле-ловушка даёт 200 без доставки и без кулдауна.
14. Два одновременных запроса с одного IP дают ровно одну доставку.
15. При недоступном Redis ответ 503 без доставки.
16. В Telegram уходит обычный текст без `parse_mode` с именем, контактом, сообщением и языком.
17. В ключах Redis и в логах нет IP в открытом виде.
18. Сквозные тесты на трёх языках: счётчик, блокировка кнопки при превышении, успех, обратный отсчёт после 429.
